# Tool-Calling Agent (`kapipe.agents.ToolCallingAgent`)

**Tool-Calling Agent** responds to a request by reasoning, calling Tools, observing Tool-call results, and generating a final answer.

The agent follows a ReAct-style execution loop. At each step, the LLM selects exactly one of the following actions:

- Call one available Tool.
- Finish with a final answer.

```text
Request
  -> Reason
  -> Call a Tool
  -> Observe the Tool-call result
  -> Reason again
  -> ...
  -> Generate a final answer
```

The agent is not tied to a specific Tool or knowledge source. For example, a dense retriever can be wrapped as a Tool, but retrieval is only one possible form of Tool use.

## Tool Interface

A Tool is represented by `kapipe.agents.Tool`.

Each Tool has the following fields.

| Field | Type | Description |
|---|---|---|
| `name` | `str` | Unique name used by the LLM to select the Tool |
| `description` | `str` | Natural language description of the Tool |
| `input_schema` | `dict[str, Any]` | Description of the expected Tool input |
| `output_schema` | `dict[str, Any]` | Description of the Tool output |
| `function` | `Callable[[Any], Any]` | Function executed when the Tool is called |

The Tool specifications are included in the LLM prompt. Tool names must be unique within an agent.

The input and output schemas describe the Tool interface to the LLM. They are not used for runtime schema validation. The Tool function is responsible for handling its input and returning the expected output.

Tool outputs must be JSON-serializable because they are included in subsequent LLM prompts.

## Tool-Calling Agent

`ToolCallingAgent` is initialized with an LLM and a list of Tools.

| Argument | Type | Default | Description |
|---|---|---|---|
| `llm` | `BaseLLM` | — | LLM used for reasoning, Tool selection, and answer generation |
| `tools` | `list[Tool]` | — | Tools available to the agent |
| `prompt_template_name_or_path` | `str` | `"tool_calling_agent_01"` | Built-in prompt template name or custom template path |
| `max_steps` | `int` | `10` | Maximum number of LLM decisions |
| `temperature` | `float` | `0.0` | Temperature passed to the LLM |
| `fallback_answer` | `str` | `"NO ANSWER"` | Answer returned when the agent reaches `max_steps` |

## Input

The `infer()` method takes a request as a string.

```python
trajectory = agent.infer(
    initial_input="Which treatment was associated with neutropenia?",
)
```

Optional metadata can be attached to the resulting trajectory.

```python
trajectory = agent.infer(
    initial_input="Which treatment was associated with neutropenia?",
    metadata={
        "request_id": "request#001",
    },
)
```

The metadata is recorded but is not inserted into the standard LLM prompt.

## ReAct-Style Execution

At each step, the LLM receives the following information:

- The initial request.
- The available Tool specifications.
- The execution trajectory from previous steps.

The LLM must return exactly one JSON object representing either a Tool call or a final answer.

### Tool Call

A Tool call contains exactly the following fields.

For example, the following JSON object represents a Tool call to a passage retrieval Tool.
```json
{
    "thought": "Relevant evidence is required to answer the request.",
    "action_type": "use_tool",
    "tool_name": "passage_retrieval",
    "tool_input": {
        "query": "Which treatment was associated with neutropenia?"
    }
}
```

The agent executes the selected Tool and records its output in the execution trajectory. The Tool-call result is then included in the next LLM prompt as an observation.

### Final Answer

A final-answer action contains exactly the following fields.

```json
{
    "thought": "The retrieved evidence is sufficient to answer the request.",
    "action_type": "finish",
    "answer": "The treatment was associated with neutropenia."
}
```

The agent stops when the LLM returns a `finish` action.

If the agent reaches `max_steps` without a `finish` action, `trajectory.final_answer` is set to `fallback_answer`. In this case, no final-answer step is added to the trajectory.

## Output

The `infer()` method returns an `AgentTrajectory`.

### `AgentTrajectory`

| Field | Type | Description |
|---|---|---|
| `initial_input` | `str` | Original request |
| `agent_steps` | `list[AgentStep]` | LLM decisions and their resulting actions |
| `final_answer` | `str \| None` | Final answer or configured fallback answer |
| `metadata` | `dict[str, Any]` | Optional request metadata |

### `AgentStep`

| Field | Type | Description |
|---|---|---|
| `llm_input` | `str` | Complete prompt passed to the LLM |
| `llm_output` | `str` | Raw output generated by the LLM |
| `action_type` | `"use_tool" \| "finish"` | Action selected by the LLM |
| `thought` | `str` | Brief reason for selecting the action |
| `tool_name` | `str \| None` | Name of the selected Tool |
| `tool_input` | `Any \| None` | Input passed to the selected Tool |
| `tool_output` | `Any \| None` | Output returned by the selected Tool |
| `final_answer` | `str \| None` | Final answer produced by a `finish` action |

## Usage

The following example wraps a Passage Retrieval component as a Tool and passes it to the agent.

The Passage Retrieval component and its index are initialized independently of the Tool-Calling Agent.

```python
from typing import Any

from kapipe.agents import AgentTrajectory, Tool, ToolCallingAgent
from kapipe.llms import OpenAILLM
from kapipe.passage_retrieval import Qwen3Embedding


# Instantiate the Passage Retrieval component
retriever = Qwen3Embedding(
    model_name="Qwen/Qwen3-Embedding-0.6B",
    max_passage_length=8192,
    normalize=True,
    metric="inner-product",
    query_instruction=(
        "Given a question, retrieve relevant passages "
        "that answer the question."
    ),
)

# Load the prebuilt Passage Retrieval index
retriever.load_index(
    index_dir="/path/to/index",
)

# Wrap the Passage Retrieval component as a Tool
passage_retrieval_tool = Tool(
    name="passage_retrieval",
    description=(
        "Retrieve passages relevant to a natural-language query. "
        "Use this Tool to obtain factual evidence before answering "
        "a request."
    ),
    input_schema={
        "query": {
            "type": "str",
            "description": "Natural-language query.",
            "required": True,
        },
    },
    output_schema={
        "passages": {
            "type": "list[dict[str, Any]]",
            "description": (
                "Retrieved passages ordered by relevance "
                "to the query."
            ),
        },
    },
    function=lambda tool_input: {
        "passages": retriever.search(
            queries=[tool_input["query"]],
            top_k=10,
        )[0],
    },
)

# Instantiate the LLM
llm = OpenAILLM(
    model_name="gpt-5.4-nano",
    max_new_tokens=8192,
)

# Instantiate the Tool-Calling Agent
agent = ToolCallingAgent(
    llm=llm,
    tools=[
        passage_retrieval_tool
    ],
    max_steps=10,
)

# Run the ReAct-style inference loop
trajectory: AgentTrajectory = agent.infer(
    initial_input=(
        "Which metastatic breast cancer treatments were linked "
        "to an adverse event also reported in dogs treated "
        "with lomustine?"
    ),
)

# Read the final answer
print(trajectory.final_answer)
```

## Custom Prompt Templates

A custom prompt template must contain the following placeholders.

| Placeholder | Description |
|---|---|
| `{initial_input}` | Original request |
| `{tool_specifications}` | JSON representation of the available Tools |
| `{execution_trajectory}` | JSON representation of previous agent steps |

The LLM output must follow the Tool-call and final-answer formats described above.
